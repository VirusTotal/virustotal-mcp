# vt-mcp 0.9.0

Agents can request standard VirusTotal analysis for URLs, domains and IP addresses
with `submit_url`, `reanalyze_domain` and `reanalyze_ip`. Each operation requires a
caller-generated canonical lowercase UUIDv4 `request_id`, retained before sending.
`get_submission` accepts exactly one file SHA-256 or network request ID.
`get_analysis` accepts the network receipt's request ID to select the intended
operation when upstream analysis IDs recur. Existing file calls and responses remain
compatible.

Network writes use VTAI's JSON submission endpoint, existing credentials and quotas.
There is no per-call confirmation, direct VirusTotal call, new local state store or
automatic POST retry. Interrupted writes recover their same receipt. Confirmed input,
permission and quota rejections retain a terminal, actionable receipt; unknown remains
unknown. Standard sharing applies. OAuth network writes require their own
`vt:network-analysis:write` permission; older grants do not expand automatically.

```sh
uv tool install --upgrade --python 3.12 --default-index https://pypi.org/simple 'vt-mcp==0.9.0'
```

Update pinned client commands or use the [setup guide](https://ai.virustotal.com/connect/mcp).
Keep credentials and file submission receipts. Hosted HTTP clients use the deployed
service; local tools require its compatible network-analysis endpoints. Agy, Claude
Code and Codex remain the primary setup recipes.

Package validation covers SDK tool contracts, JSON proxying, request-ID selection,
closed errors, uncertain recovery and file compatibility using synthetic local
transports. It does not certify every client or model workflow. See
[analysis and recovery](../analysis.md) for the API shapes, sharing and recovery rules.
Apache-2.0; earlier releases remain unchanged.
