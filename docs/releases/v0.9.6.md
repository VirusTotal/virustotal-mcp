# vt-mcp 0.9.6

Hosted adapters can enable `submit_chatgpt_file` for ChatGPT attachments using
the official `openai/fileParams` descriptor. The optional binding requires file
receipt and analysis readers. The adapter enforces download destinations, size,
deadlines and the existing write permission; local stdio has no new downloader.
The tool returns the original file's SHA256 for the existing receipt recovery.
No uncertain upload is automatically repeated.

A small packaged client contract now supplies Claude Code setup commands,
Node.js 22+ requirements and the credential-name rule to generated documentation,
the Claude plugin and compatible hosted setup pages. This covers the first
shared client segment, not every client or configuration field.

Claude Code plugin 0.1.2 extends its pre-read filename guard to `.p12`, `.pfx`,
`.ppk`, `.jks`, `.keystore`, `.git-credentials`, `.pgpass` and `.htpasswd`.
Valid file expansion still returns `allow`; the filename precaution does not
inspect contents or replace sensitive-content consent.

The hosted attachment tool becomes available when the backend deploys its
binding. Package and protocol tests do not establish a native ChatGPT attachment
workflow. Refresh the connection's tools if its inventory predates that deployment.
PyPI does not install the separate Claude Code plugin. Authentication, scopes,
quotas and repeated-query accounting are unchanged.
